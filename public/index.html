# Introduction

Abstract Data Types (via Data Structures) allow us to create more advanced and efficient algorithms. They do this by providing more efficient ways of accessing the data we are using in our algorithm. This can decrease the time and space complexity of algorithms, in addition to simplifiying the logic (making them easier to follow).

## Data Structures

DSs are concrete implementations that define how the data is actually stored in memory, and how it is accessed.

Arrays -> sequentially stored values in memory:

  • O(1) for reading data
  • O(1) for appending values to the end
  • O(n) for adding or removing values within (values must be shifted up)

Linked Lists -> values stored as nodes in a chain, with each node pointing to the next:

  • O(n) for reading data within the array
  • O(1) for reading or adding data to the head

Trees -> Each node must have one parent, and can have many children. Essentially a linked list.

### Abstract Data Types

ADTs define operations that you can apply to them. They can be thought of as an interface, you dont need to know anything about the implementation, you can simply just use the defined operations.

Stacks -> FIFO, best implemented by an array, its operations are:

- pop, removes an element from the top - push, adds an element to the top Queue -> FILO, best implemented with a linked list

  • enqueue, adds an element to the start
  • dequeue, removes an element from the end

Binary Trees -> Each node can have at most two children, where the left child has a value less than the parent, and the right has one greater

  • delete in O(log n) time
  • add in O(log n) time
  • searching in O(log n) time

*if the tree becomes unbalanced (multiple values that are greater than the last are added) then operating in the tree starts to trend towards linear time. -> this is where self balancing trees come in, they preserve the balance*

Self-Balancing Trees -> A type of tree that preserves its balance by performing 'rotations' when sub-branches get too long. This keeps the tree shallow and therefore fast!

- A rotation is where a parent node and one of its children are 'roatated' around, this can shorted a tree if one of its subtrees is longer than the other. - Everytime a deletion or insertion occurs in the tree, it checks itself to see whether it needs to rotate (via a set of conditions), this this preserves O(log n) time for its operations. - One example of this is the Red-Black tree Hash Maps -> Store 'hashable' keys, that when inputted into a hash function return an index in an array, where a value can be stored.

  • addition, deletion and retrieval is O(n) (in an optimised HM)

*There are different implementations to avoid collisions (when two different keys hit the same index in the array)* -> linear programming, if a collision occurs during an operation then while entries in the array are not none traverse the array, until you find a place to insert (this happens for every element), obviously as the list gets fuller operations deteriorate to O(n) -> chaining, if a collision occurs then at that index a linked list is created (in the py implementation, if that list becomes too large it is turned into a RB tree)

Tries -> Trees with a variable number of nodes

  • adding or checking for presence of a word within a trie is O(n) (if the trie is implemented with hashmaps)

*They are best for finding suffixes*

Graphs -> Made up of verticies (nodes) and edges (joins between in verticies)
